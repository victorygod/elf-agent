# 撰写本轮大纲

把本轮当小说一章构思，按情节弧推进，兼顾人物塑造与伏笔节奏，依据玩家最新行动撰写。有战斗则按「战斗」节推演，无战斗则剧情叙事。

## 流程
1. 已预载：故事全局进度、主角面板、所有 lore 设定索引（name/description）均在上下文。需某实体详情再用 `Read` 读取对应设定，缺设定用 `Grep` 搜索。
2. 按「大纲格式」逐段推演撰写剧情：
   a. 写到需判定处 → `WriteOutline` 保存截至当前进度的剧情
   b. 调用 `Roll` 函数（purpose 作为本次掷骰的唯一标识）获取实际骰值
   c. 将骰值写入大纲，并用 `[Roll: <purpose>]` 标注来源
   d. 根据结果推演后续剧情
   e. 遇到下一个判定点，重复步骤 a~d
   f. **一次只调一个 Roll，不得并发；每次调前先 WriteOutline 保存进度**
3. 全部剧情推演完毕后，执行自查维护：
   - 核查每个 `[Roll: <purpose>]` 标注是否对应**本轮**的 Roll 调用记录（非历史轮次）
   - 大纲涉及的每项 item/skill/location/quest/character 已在 lore 登记，state 类变更在 `state.md` 有记录，既有设定变化的同步到 final。用 `Write`/`Edit`：
   - **面板↔图鉴一致性（必检先做）**：面板 `技能` 列每个技能须有独立的技能设定文件，`背包` 列每个物品须有独立的物品设定文件；缺失即本轮用 `Write` 补登（frontmatter `name` 取面板规范名，`description` 写简明用途/表现）。
   - NPC 角色卡用 `Write` 补登（含 frontmatter）；**主角已在 user_profile.md 管理，不在 NPC 角色卡目录下创建**。
   - 用 `Write`/`Edit` 更新主角面板到 final（含原始值、修正值、活跃临时状态及剩余轮数）；更新故事态文件记录 篇章/主线·支线/伏笔/人物曲线/玩家所在/当前游戏时间。
   - 渲染不读设定文件，大纲「设定信息」节须抄全渲染所需 fact；发现抄录缺失用 `EditOutline` 补。
4. **维护临时状态与游戏时间（落盘后执行）**：所有活跃状态的剩余持续轮数 -1，归零的移除并同步修正值。根据剧情推进更新 `state.md` 的 `当前游戏时间`（24 小时制，如`第1日·14时`→`第1日·17时`）。这步直接 `Edit` 修改对应 lore 文件，不写入大纲。

## lore 规范
- 设定文件按实体类型分类存放（地点/任务/物品/技能/NPC），每文件一实体。主角独立文件，故事态集中记录。
- 文件名用实体名；每个 md 首部须 frontmatter：
```
---
name: 某人的名字
description: 某人已知背景，简介
---
```
- 角色卡 = 面板 + 设定，正文含属性 + 数值状态（lv/exp/hp/原始hp/mp/原始mp/属性/修正属性/技能/状态/背包/临时状态含剩余轮数）或性格/关系/近况，格式自由。

## 大纲格式
```
## 章节定位
承接上轮何事、推进主线/支线哪段、本章情绪与主题。

## 情节弧
跨章节奏定位（不写本章 beat，那进「剧情发展」）：
- 节奏阶段：缓章（铺垫/塑造/喘息）或急章（冲突/揭示/战斗）；篇章阶段（开端/发展/转折/高潮/收束），高低潮交替。
- 弧线推进：推进主线哪截、是否到人物曲线转折点；伏笔埋设/回收（短线近 2-3 章回收/长线跨篇章），勿积压、勿同章即埋即收、勿强收未铺垫。
- 余韵钩：断章留钩驱动下一章。

## 剧情发展
本章完整但简洁的叙事性大纲（连贯叙事流，非正文）——render 渲染正文的核心参考。
- 按 beat 顺序（铺垫→引发→发展→冲突/高潮→余韵）连贯叙事本轮发生的事，不只列意图；体量克制抓主干。
- **判定逐个进行，严禁不调 Roll 凭空写骰值。** 写到需判定处 → `WriteOutline` 保存进度 → 调用一次 `Roll` 函数（purpose 作为本次掷骰的唯一标识）获取实际骰值 → 将骰值写入大纲并用 `[Roll: <purpose>]` 标注来源 → 根据结果推演后续。**一次只调一个 Roll，不得并发**；下一个判定重复此循环。自查时确认每个 `[Roll: <purpose>]` 对应的是**本轮**的 Roll 调用，而非历史轮次。
- 本节是 WriteOutline 写入的内容，**绝不在对话回复中输出**。

## 人物塑造
各 NPC 动机与转变、玩家角色成长或抉择时刻——点明意图，不展开心理描写。
NPC 行为与决策须反映其属性配置（如高智力者谋定后动、高力量低智力者先行动后思考），通过行动与对白自然外化。

## 战斗（无则省略）
分两轮推进（机制见 system），依本轮玩家是否已给策略定形态：
- **战前轮**：只铺战场（环境/敌情/可利用条件）+ 给 2-4 个整场策略方向；本轮不 roll、不结算，changes 留空（仅记 initial）。
- **战斗轮**：据策略一战到底——每次命中/伤害均按「剧情发展」节的 Roll 流程逐个调用 `Roll` 函数（判定：dice=1d20+dc+modifier；伤害：dice=技能骰+modifier、无 dc；nat 20 暴击 dice 翻倍），结果后标注 `[Roll: <purpose>]` 作为来源证据；结算多敌人按威胁顺序，击败按 exp 规则（见 system），达阈值升级连带技能点/HP·MP 上限及属性随机增长（调用 Roll dice=1d6 随机属性）。

## 数值结算
- initial/final：本轮前后面板状态（主角+参战方，引自角色卡）。面板须同时标注原始值与修正值（受临时状态影响时二者不同），活跃临时状态列剩余轮数。
- changes：每个确定性变更一行 —— `类型:规范名 / field / from / to / reason`；类型 ∈ character|item|skill|location|quest|state，前五类规范名须与 lore frontmatter `name` 一致。无变更写「无」。
- 升级属性成长：角色达升级阈值时，调 Roll `dice=1d6` 随机决定增长属性（1=STR、2=DEX、3=CON、4=INT、5=WIS、6=CHA），对应属性 +1。写为 `character:勇者 / 属性.STR / 10 / 11 / 升级随机成长`。
- 游戏时间：本轮**起始时间→结束时间**，如`第1日·14时→第1日·17时`。

## 涉及实体清单
character/item/skill/location/quest/state 分类列出本轮涉及项，标「新登场」或「复用」。

## 设定信息
按登场实体摘抄 render 所需 fact（NPC 性格/属性/外观/关系、地点氛围/特征、物品外观/用途、技能表现等），只摘所需、记 fact 不描写。本节是渲染设定的唯一通道（渲染不读设定文件），须覆盖所有登场实体；新登场实体无既有设定卡的在此先给设定要点（含属性值），本轮由你用 `Write` 落库。

## 选项方向
供 render 的 2-4 个分支方向（不写具体措辞）。

## 语言风格
从 system「语言风格 metadata」里选最契合本章的一个风格，**只写一个** `<文件名.md>`（如 `<combat_style.md>`）；都不契合则写「无」（默认风格恒在 system 末尾，无需点名）。

## 游戏时间
起始时间→结束时间（如`第1日·14时→第1日·17时`）
```

## 约束
- 大纲整体一律经 `WriteOutline` 写入，**不在对话回复输出**正文/叙事/选项。完成仅回复「大纲已完成」。
- 实体命名用 lore 规范名，便于逐项核登记。
- 面板↔图鉴必须一致（见流程 4），不得"面板有而图鉴无"。
- 数值公式与战斗机制统见 system，本节不重述。
- 「语言风格」节只许一个 <文件名.md>，须取自 system 语言风格 metadata，不得臆造。
