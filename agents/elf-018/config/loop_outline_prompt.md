# 撰写本轮大纲

把本轮当作**小说的一个章节**来构思：按情节弧（铺垫 → 引发 → 发展 → 冲突/高潮 → 余韵）推进，兼顾人物塑造与伏笔节奏。依据对话历史中的玩家最新行动撰写。战斗只是场景之一——有战斗则按「战斗」节完整推演，无战斗则是剧情叙事。

## 流程
1. 先 `Read` 全局进度 `state.md`（篇章进度 / 主线·支线 / 待回收伏笔 / 人物曲线 / 玩家所在）与相关角色卡/设定（主角 + 本轮登场 NPC / 地点；敌人若有也读）作为基线；缺设定时用 `Grep`/`Glob` 检索（路径见 metadata）。
2. 按下方「大纲格式」构思本章；需判定处调用 `Roll`；涉及战斗时按「战斗」节完整推演。
3. 用 `Write` 写到任务指令给出的路径。

## 大纲格式

```
## 章节定位
本章在全局的位置：承接上轮何事、推进主线/支线的哪一段、本章的情绪与主题。

## 情节弧
按 beat 顺序列情节意图（不加描写）：
- 铺垫：场景、氛围、引入的人物或信息。
- 引发：打破平常的事件或抉择点。
- 发展：试探、推进、埋设伏笔。
- 冲突/高潮：本轮的核心对抗或揭示（若为战斗见下节）。
- 余韵：收束、留白、断章钩。

## 人物塑造
各 NPC 的动机与转变、玩家角色的成长或抉择时刻——点明意图即可，不展开心理描写。

## 战斗（若有；无则省略本节）
战斗不直接开打，分两轮推进，依本轮是否已收到玩家策略选择形态：
- **战前轮**（玩家尚未给出策略）：只铺战场——环境、敌情、可利用条件；本节给出 2-4 个整场战斗策略方向（强攻/潜行/交涉/利用地形…）；本轮**不 roll、不结算**，数值结算 changes 留空（仅记 initial）。
- **战斗轮**（玩家已给出策略）：据策略推演整场战斗，一战到底——
  - 判定：每次 roll 一行 —— 用途 / 技能 / DC / modifier / 骰值 / 结果。
  - 结算：多敌人按威胁顺序；击败按 `exp = 敌人等级 × 20`（敌人等级 ≤ 玩家 −2 不给），达阈值升级并连带技能点 / HP·MP 上限。

## 数值结算
- initial / final：本轮前后面板状态（主角 + 参战方，引自角色卡）。
- changes：每个确定性变更一行 —— `类型:规范名 / field / from / to / reason`。
  类型 ∈ character | item | skill | location | quest | state；前五类规范名须与 lore frontmatter `name` 一致，state 类指 `state.md` 内对应字段/记录。
  无变更则写「无」。

## 涉及实体清单
- character / item / skill / location / quest / state 分类列出本轮涉及项，标注「新登场」或「复用」。

## 设定信息
- 按本轮登场实体摘抄 render 所需设定 fact（NPC 性格/外观/关系、地点氛围/特征、物品外观/用途、技能表现等），只摘所需、记 fact 不描写。
- render 不读 lore，本节是大纲供给 render 设定的唯一通道，须覆盖所有登场实体；新登场实体若无既有 lore，在此先给出设定要点，供 reviewer 落库。

## 选项方向
- 供 render 的 2-4 个分支方向（不写具体措辞）。
```

## 跨章节奏把控
本章必先从全局弧线视角定位，再落到章内情节：
- **篇章阶段**：判明当前处于本篇章的开端 / 发展 / 转折 / 高潮 / 收束，据此定本章是缓章（铺垫、塑造、喘息）还是急章（冲突、揭示、战斗）；高低潮交替，勿连续高潮、勿连续平淡。
- **主线推进**：每章推进主线一截，不一章解完、不连章停滞；本章推进哪截写进「章节定位」。
- **支线交织**：支线穿插主线之间作喘息与丰度，最终回扣主线或主题；勿与主线争夺焦点。
- **伏笔长短线**：区分短线（近 2-3 章回收）与长线（跨篇章）；本章按节奏埋设或回收——勿积压不收、勿同章即埋即收、勿强收未铺垫之伏笔。
- **人物曲线**：主角与 NPC 的转变分布到多章，本章若到转折点则在「人物塑造」点明，避免单章突变。
- **前后呼应**：与过往章节的意象、情境、台词有意呼应或对照。

## 剧情节奏
- **伏笔**：埋设轻描淡写，回收前再铺垫一次；不在本轮强解，留待后续轮。
- **断章**：每轮结尾留钩（悬念 / 新信息 / 选项），驱动玩家下一步。

## 约束
- modifier = 技能等级加成 + 状态加成；伤害 = 技能骰 + 技能等级加成 + 状态加成（详见规则）。
- 大纲列情节意图而非描写，不承担叙事正文。
- 实体命名一律用 lore 规范名，便于 reviewer 覆盖性校验逐项核登记。
- 「设定信息」节只摘 render 所需 fact、不描写；它与「大纲列意图不描写」不矛盾——摘抄的是必需素材，非叙事。
- **render loop 不读 lore 设定集**，无法自行查阅角色卡/地点/物品等详情。因此大纲在「情节弧」和「人物塑造」中须抄录 render 所需的关键设定信息（NPC 性格特征、地点氛围、物品外观/效果等），使 render 据此渲染即可，无需检索。

最终回复，大纲完成即可，不需要多余回复。
